Inline select + note side by side (compact)

Same starting point as Option A/D (status select inline in .form-grid), but the status note is a narrower text input placed directly beside the select, in the same row/cell — always visible, no icon, no toggle. Trades note width for keeping the status cell to one field-row of height, same as any other field.

Annotation notes

  • Blank status (Dòng 2): select shows the placeholder option "— Chưa có —", dashed left-border, muted grey text — a real, selectable, empty-string option, never coerced to the first status key (draft). Its note input sits beside it, empty, with an italic muted placeholder "Chưa có ghi chú" — entering a note doesn't require picking a status first.
  • Disabled (Dòng 3): user lacks change_status on this line — select AND note input both carry disabled, greyed via the existing .field input:disabled rule, current values still visible/read-only, plus the inline "Không có quyền đổi trạng thái" tag below.
  • Compact by construction: select gets ~58% of the cell width, note gets ~42% (min 84px) — no extra row is added to the grid vs. option-a's base 6-field layout, so total line-card height stays closer to the original design than Option D.
  • Field label shortened: "Ghi chú trạng thái" → "Ghi chú" to fit the narrower column without wrapping onto two lines at small widths.
  • 360px tradeoff (see frame below): the real risk here isn't extra height, it's width — cramming a select + text input into one grid column (which is already the full 360px card width) makes both controls noticeably narrower than every other field in the form. Tradeoff summary vs Option A

Also removes Option A's icon-toggle guesswork like Option D, but keeps the status cell to a single field-row height by placing the note beside the select instead of below it — closest to Option A's original footprint. The cost shifts from height to width: at 1280px (3-col grid) the combined cell is comfortable, but at 360px (1-col, full card width) squeezing select + note into one row makes both controls visibly narrower than every other field, and long note text will need to scroll/truncate inside a ~84-120px input. Best when notes are expected to stay short (a few words) and row height matters more than note field width.
