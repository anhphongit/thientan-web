Mockup · Option C

Dedicated status column

Restructures the lines list from today's stacked .line-cards into a real <table> so status gets its own explicit column, with the status note shown as a truncated second line (title-attribute tooltip on hover/long-press). Most scannable at a glance across many lines — but it's the biggest structural change of the three, and honestly the worst at 360px.

Annotation notes

  • Set status (Dòng 1): "Đã xác nhận" pill in its own column; status note truncates to one line underneath with title= for the full text on hover.
  • Blank status (Dòng 2): dashed "Chưa có trạng thái" badge — same non-status-pill treatment as the other two mocks, so it can't default-render as draft.
  • Disabled (Dòng 3): status column shows a greyed, non-interactive value box (not a real <select> control look) plus the permission tag, consistent with mocks A/B.
  • Structural cost: unlike A/B, adopting this means converting the whole lines list from cards to a table — a materially bigger diff against the current lineHtml() in ViewsOrders.html.

Tradeoff summary

Most scannable when many lines are on screen — every status is aligned in one column, easy to compare at a glance. But it's the worst option at 360px (forces horizontal scroll to even see the column) and the biggest implementation diff, since it replaces the existing card-based lines list with a table rather than extending it.
